# 08 · 使用与原理说明（v0.4.6）

> 面向使用者的功能说明：每个功能"怎么用 + 背后怎么想的"。规则细节以 docs/02 为准，本文讲逻辑。## 1. 扫描：项目是怎么被识别出来的

### 1.1 从目录到项目

- 「扫描根」列表（设置里可配多个，每行一个目录）下的**一级子目录**各算一个项目，目录名（文件夹名）就是项目列显示的名字。
- 隐藏目录（`.`/`_` 开头）、`node_modules`、`__pycache__`、`.rar` 文件不算项目。
- **缓存**：每个项目以"目录 mtime 快照"为键缓存检测结果，没改动的项目下次扫描直接复用，秒级完成。按住 **Shift 点「重新扫描」** = 无视缓存全量重检（文件内容变了但时间没变的兜底）。
- **启动时自动扫描**开关（工具栏）：关掉后启动直接显示上次结果、完全不碰磁盘；F5 / 重新扫描仍可手动刷。

### 1.2 一个项目内部看什么（扫描单元）

项目根 + 一级子目录（排除重目录）+ 白名单目录（frontend/backend/server/web/app/h5-app/client/editor/sites）再下钻一层。每个单元按规则表 R1→R9 依次尝试，**同单元先命中先用**；项目命中任何"真服务"规则后，其余单元的静态页不再列为启动项（它们是附属品）。

### 1.3 规则表速览（R1~R12，详见 docs/02）

| 规则 | 认什么 | 生成的启动项 |
|---|---|---|
| R1 | 启动脚本（启动.bat / start.cmd / *.ps1，名字含启动词或内容调解释器） | 独立黑窗运行，端口从脚本内容提取 |
| R2 | 自带运行时（runtime/python.exe） | 不生成项，Python 启动自动改用它 |
| R3 | package.json 的 dev/start 脚本 | `npm run dev`（Vite 端口从 vite.config 读） |
| R4 | **带 spring-boot-maven-plugin 的 pom.xml** | `mvn spring-boot:run`，端口读 application.yml |
| R5 | project.godot / .NET | 成品 exe 或构建命令 |
| R6 | 单个 jar | `java -jar` |
| R7 | *.pyw | pythonw 无控制台启动 |
| R8 | serve.js/server.js（无 package.json 时） | `node serve.js [端口]` |
| R9 | index.html（含 PWA：manifest+sw） | 静态页直开 / 精灵内置 http 托管 |
| R10 | Python 入口（main.py / 包 __main__） | `python main.py` / `python -m 包` |
| R11 | 以上都不中 | 文档型，灰显，双击=打开目录 |
| R12 | **dist/ 里的打包成品 exe**（PyInstaller、.NET 发布等；v0.4.3） | 直接运行该 exe；与源码启动项并列 |

**R12 与其他规则的关系**（v0.4.3）：它只看项目 `dist/` 一层内的 exe，且是**附加项**——和源码启动方式（R10 跑 main.py）并列显示，想跑源码跑源码、想跑成品跑成品。`build/windows/` 的 Godot 成品仍归 R5。两类噪音自动排除：.NET 发布自带的 `createdump.exe`（崩溃转储工具，不是应用）和名字带 setup/install/update 的安装器。注意打包成品可能与源码不同步——卡片备注里有提醒，拿不准就重打包再跑。

**v0.4 的 R4 门槛**：pom.xml 必须声明 `spring-boot-maven-plugin` 才算可运行的应用模块。多模块 Maven 工程（如 ModularSuite：admin/common/framework/generator/quartz/system/pdf + 聚合根）里，聚合根（packaging=pom）和纯库模块没有这个插件，`mvn spring-boot:run` 对它们要么报错要么无意义——所以**只列真正能跑的模块**（ModularSuite 只出 ca-client-admin，端口 8014）。这也回答了"为什么会有 8 个启动项"：旧规则见 pom 就列，v0.4 起按插件过滤。

**R4 标签规则**：一个项目只有一个后端项时叫「后端服务」；多模块工程按模块区分（「后端服务（ca-client-admin）」）。之前 Q7 显示「Maven 服务」是旧规则"pom 不在 backend/server 目录就叫 Maven 服务"——它的 pom 在项目根，v0.4 统一成了「后端服务」。

### 1.4 端口从哪来

优先级：脚本/配置内容提取（set PORT=、--port、application.yml 的 server.port、vite.config 的 port、listen(...)）→ **端口知识库**（profiles.json 里"项目→惯用端口"的学习表，日志回读到新端口会自动记）→ 框架默认（Vite 5173 / Spring 8080）。列表"端口"列 = 该项目所有启动项的去重端口。

## 2. 启动：点一下按钮发生了什么

1. **预检**：命令在不在 PATH、node_modules 缺不缺、端口被谁占（psutil 查占用进程，精灵自家的会点名）。
2. **命令组装**：`.bat/.cmd` 统一 `cmd /c <全路径>` 包装（含 PATH 上的 npm.cmd/mvn.cmd）；项目自带 `.tools/maven` 优先于 PATH；自带 runtime 的项目用 runtime 里的 python。
3. **控制台显示方式**（v0.4 总设置）：
   - **集中到精灵运行窗**（默认）——输出捕获进日志文件和运行日志页，可按项目着色过滤；
   - **各项目弹原始控制台**——像手动开黑窗一样，各窗独立（代价：精灵看不到输出、无法端口回读）。
   - 例外：项目自带的交互启动脚本（R1 的 启动.bat 这类要盯着的）永远弹自己的窗口。
4. **开浏览器的时机**：有端口的服务**等端口真正监听后**再开（最长 30s，且监听进程必须属于本次启动的进程树）；无预设端口的服务靠日志回读 `http://…:端口` 命中即开。URL 一律用 `localhost`（Vite 6 只监听 IPv6 ::1，写 127.0.0.1 会打不开）。
5. **启动失败/一闪而过怎么办**（v0.4.3）：
   - 普通服务、桌面程序（含 dist/ 打包成品）的输出**默认被精灵捕获**（stderr 也并进来）——崩溃报错会直接出现在「运行日志」页和日志文件里，不会一闪而过；失败时运行窗会补一行红色提示（exit code 与存活时长）。
   - 独立黑窗方式启动的项（交互启动.bat、或设置了"各弹原始控制台"），精灵看不到它的输出；如果它**几秒内就退出且退出码非 0**（典型的一闪而过），会弹窗问你要不要**「捕获重跑」**——点"是"就换个方式再跑一次（不弹黑窗、输出全部抓进运行日志），报错立等可看。诊断重跑不影响交互脚本平时的正常行为。
   - 命令/文件本身找不到这类本机问题（如 exe 被移动），启动时直接弹人话错误，不闪不崩。
6. **停止**：`taskkill /T /F` 按进程树杀（cmd→npm→node 一串全干净），并确认端口已释放。

**「访问」按钮**（v0.4）：启动和访问是两件事——服务已经在跑、或只想再开一次页面时，点「访问」直接用设置里的浏览器打开该启动项的 URL，不碰进程。凡是有 URL 的启动项（服务/静态页/内置托管）都有这个按钮。

## 3. 名称 / Logo / 分组 / 排序

- **显示名三级**：你标注的中/英文名（项目属性里改，永远优先）＞ 扫描猜测 ＞ 目录名。猜测来源按命中率排：README 首个标题 ＞ 根/子目录 html 标题 ＞ package.json name ＞ 目录名去前缀（Tool_/G_/P_…）。猜测会自动拆中英（如「工业流程引擎（Super Industrial Flow Engine）」→ 中「工业流程引擎」/英"Super Industrial Flow Engine"），作为属性框的预填预设。
- **Logo 独列**：自动识别 logo/icon 开头的 png/gif（≤2MB，从严——识别不出的不硬凑），也可在项目属性里手动指定；列表 18px、详情 40px。
- **分组**：项目属性里填分组名即建组；列表按分组头行（▾/▸ 可折叠）平铺展示；把项目拖到分组头行上=入组，拖到"未分组区"的项目上=移出组。**留空 = 自动按父文件夹分组**（v0.4.4：配了多个扫描根时，各根的项目自动归到以根名命名的组；只有一个根或待自动分组的项目都来自同一个文件夹时不显示组头，列表保持平铺）；填 `-` = 显式不分组。**只在 nginx 里的站点**（Nginx_ 前缀，v0.4.5）默认归入「nginx」组；本机有多份在用 nginx 配置时按来源分「nginx(配置路径)」组，单根工作区里也只有这一组头。
- **排序**：手动序是默认（拖动排位 / 右键上移下移，顺序存 profiles.json 的 order 段，重启保留）；点列头按该列排序，再点反向，第三下回到手动序（三态，箭头 ▴/▾ 指示）。

## 4. 详情页

- **启动项卡片**：命令、端口、运行状态；[启动/停止] 按钮常驻右侧，有 URL 的还有 [访问]。
- **常用信息**：数据库连接（application*.yml/properties 的 datasource，`${ENV:默认值}` 显示默认值）、前端代理目标（vite.config proxy）。**密码永不显示**。
- **关键配置**（直显）vs **次要配置**（默认折叠，点标题展开）：
  - 关键 = 直接决定"跑起来什么样"的文件——application*.yml/.properties（含 -mysql/-druid 等 profile 变体）、.env、docker-compose.yml、vite.config.*、project.godot、config.js；
  - 次要 = 工程描述类——pom.xml、package.json、tsconfig.json、requirements.txt、pyproject.toml、setup.py、webpack.config.js、README.md。
  - 每个文件：双击文件名或[打开] = 系统默认方式打开；[所在目录] = 资源管理器定位到它。
  - 扫描位置：项目根 + 一级子目录 + Spring 深层约定位置（根/backend/server 的 `src/main/resources`，以及 Maven 模块目录下的同名位置）。

## 5. 日志

- 运行输出实时进底部「运行日志」页（按项目着色，可只看选中项目）+ 落盘 `logs/{项目}_{日期}_{序号}.log`（1MB 分卷，跨天自动切）。
- v0.2.4 起每项目可配置：输出到自定义目录、保留天数；工具栏【🧹 清理旧日志】按日期全量清理（只动精灵标准命名的文件，永不碰你的手动备份）。

## 7. 常见疑问

- **为什么有的项目 8 个启动项、有的 1 个？** 多模块 Maven 工程每个带 pom 的模块都会命中 R4；v0.4 起只列带 spring-boot 插件的可运行模块，并以「后端服务（模块名）」区分。
- **后端为什么叫「后端服务」不叫「Maven 服务」？** 单后端项目统一叫「后端服务」；只有多模块并存时才用模块名后缀区分。
- **页面打不开？** 精灵的 URL 全用 localhost；Vite 6 只监听 ::1，手输 127.0.0.1 会拒绝连接。服务是否在跑看列表状态点与端口列。
- **改了配置文件为什么端口没变？** 端口在扫描时读取；改完 F5 重扫（或 Shift 强制重扫）即更新。
- **程序一闪而过/闪退，报错在哪看？** 看「运行日志」页——普通启动的输出都被捕获了。独立黑窗方式的闪退会弹"捕获重跑"，点一下报错就进日志。还没明白就看该项目 `logs/` 目录下的最新日志文件。
- **dist/ 里多出来的 createdump.exe 怎么没列出来？** 那是 .NET 发布自带的崩溃转储工具，不是应用入口，R12 按噪音排除（安装器类名字同样排除）。

## 8. nginx 关联（v0.4.2）

有些前端不走 `npm run dev`，而是**构建后交给 nginx 托管**（nginx 可能裸装在 Windows，也可能跑在 Docker 里）。这类项目在项目目录里看不到"启动方式"，启动方式写在**系统 nginx 配置**里——所以精灵扫描时会把系统 nginx 配置也读一遍（设置里可整体关掉）。

### 8.1 你会看到什么

| 场景 | 展示 |
|---|---|
| 项目目录被 nginx 托管（root/alias 指向它或它的 Web/、dist/ 子目录） | 详情页「Nginx 关联」：`nginx 托管前端：http://localhost:9003/`，附 root 位置（项目内子目录/本机路径/容器路径三态标注）、监听端口、来源配置文件；该 server 反代到的后端项目也列在下面 |
| 项目端口被 nginx 反代（proxy_pass 指向 localhost:你的端口） | 后端项目详情页：`被 nginx :18080 /webdocs/dataApi/ 反代 → 本项目端口 28080`。**按端口推测**，仅供参考 |
| 某站点只在 nginx 配置里出现（root 不在任何扫描根下） | 列表出现 `Nginx_<目录名>` 合成项目（类型 Nginx、端口列 = listen），"启动"= 打开访问地址；root 是本机路径时可右键打开目录，是容器路径（如 Docker 里的 /mnt/…）则标注"本机不存在" |
| 在用的 nginx 托管的是工作区里的真实项目（v0.4.8） | 这类关联会写进项目详情（上行两条），**同时**在 nginx 分组里显示 `↗ 项目名` **引用行**（类型列 `已关联 · 托管/反代`，状态点跟随目标项目）——哪怕一份配置一个站点都没有（比如裸装 nginx 托管的全是工作区项目），它也有自己可见的分组。双击引用行跳到该项目并打开详情；右键可直接打开访问地址、跳转项目或打开配置文件。引用行只是指路路标，不能启动、不能拖动排序 |

### 8.2 背后怎么找的

- **配置从哪来**：手动指定（设置里填 nginx.conf，**v0.4.7 起可填多个，每行一个**，浏览支持多选；填了无效会有提示、不瞎猜——部分无效时忽略无效的那几行并写进扫描日志，全部无效也不自动猜）＞ 运行中的 nginx 进程 ＞ PATH ＞ 各盘常见安装目录 ＞ **各盘根的 nginx.conf**（Docker 常这么挂）。可能找到**好几份在用的**——全部解析，每条关联都注明来自哪份配置；名字像备份的目录（"nginx - 副本"之类）自动跳过。
- **不想让某份配置参与（v0.4.9）**：设置里「排除的 nginx 配置」填路径（或点「勾选要排除的配置…」直接勾），被排除的彻底不参与关联扫描，扫描日志会注明；手动指定的路径同样能被排除（排除优先）。为什么不做"自动识别没用上的配置"：像挂进 Docker 的配置在 Windows 进程表里完全不可见，自动猜会把真实在用的误杀——所以交给手动勾选，确定性 100%。
- **怎么解析**：自研轻量解析器（零依赖），认识注释、带空格的引号路径、include 通配、upstream、location 嵌套；`/mnt/f/...` 按 WSL 盘挂载换算，`/opt/...` 这类容器路径如实展示。
- **精灵不管 nginx 进程**：它可能跑在 Docker 里、也可能是系统服务，代启代停容易帮倒忙——所以站点的"启动"按钮就是打开访问地址，nginx 本身的启停仍由你自己的脚本/容器管理。
- 两个开关都在**设置**里：「扫描系统 nginx 配置」（关=全部清空）与「列出仅在 nginx 里出现的站点」（关=只隐藏 Nginx_ 合成项目，已托管的真实项目关联保留）。另外（v0.4.16）：分组里**仅按端口推测**的关联条目（「可能关联」）默认不再显示——同一端口常被多个项目声明，项目拷贝会因此整批出现在分组里；想看全量就在设置里勾选「列出仅按端口推测的关联条目」。

## 9. 端口防火墙（v0.4.6）

服务在本机跑得好好的，同事从局域网访问却连不上——十有八九是 **Windows 防火墙把入站拦了**（公网/远程同理）。v0.4.6 起，给项目端口"开防火墙"是精灵里的一个正式按钮。

### 9.1 怎么用

- **单项目**：选中项目 → 详情页「端口防火墙…」（或右键菜单同名项）。对话框里勾选要开放的端口（检测到的端口已帮你勾好，也能手动补），选协议（一般 TCP）和远程范围——**默认"仅局域网（本地子网）"**，最小暴露面；确实要公网访问再选"所有远程地址"或自定义 IP 段。点「写入 / 更新规则」→ 弹 UAC 授权点「是」→ 一次批量写完。
- **总览**：工具栏「🛡 防火墙总设置」。这里列出**所有由精灵写入的规则**（哪个项目、哪些端口、什么范围、启用没有），可以批量启停（规则留着但暂不生效）、删除、一键清空（全选+删除），也能跳去系统自带的防火墙管理面板看全量。
- 规则可重复写：同一配置再点一次「写入」会先清掉旧的同名规则再写，不会越堆越多。
- **局域网还是访问不到？还差两件事（v0.4.19）**：防火墙只是前提之一——Vite 这类 dev server 默认只监听本机回环（localhost），端口放行了局域网也够不着。到设置「局域网访问」区块勾选「启动 Vite 服务时自动监听所有网卡（注入 --host）」；写入防火墙规则后精灵检测到这种情况也会**主动弹窗问你要不要开**。开关对下次启动生效，已在运行的服务**停止再启动**即可。另外两个坑：① 端口被别的服务占用时 Vite 会自动顺延到其他端口，防火墙要按服务**实际**监听的端口开放（详情页/端口总览看真实端口）；② 本机是虚拟机 NAT 网段（如 VMware 的 192.168.232.x）时，NAT 之外的物理局域网机器路由不进来，需要在虚拟网络设置里改桥接或加端口转发。

### 9.2 背后怎么做的

- **读**（打开对话框、刷新列表）：走系统防火墙的 COM 接口读规则，**不需要管理员**；只筛"描述带精灵标记"的规则——你手工建的其他规则在这里看不见、也不会被碰到。
- **写**（写入/启停/删除）：netsh 命令打包成临时脚本，经 UAC **一次授权批量执行**（不会一个端口弹一次窗）；精灵已用管理员身份运行时不再弹窗。执行结果逐条回读汇报，UAC 点了"否"就是"什么都没动"，不会留半截状态。
- **规则长得什么样**：名字是 `启动精灵_项目名_端口_协议`（如 `启动精灵_Tool_ChoiceKit_8787_TCP`），描述带精灵标记——系统防火墙控制面板里也一眼能认出哪些是精灵建的。
- **换电脑怎么办**：防火墙规则是系统状态，**不跟着精灵文件夹走**。拷到新机后端口要重新开一次（对话框会记得你上次的配置，预填好直接点写入）。不想要了就在总设置里全选删除，系统里不留痕。

## 10. 运行感知：哪些程序已经在跑、哪些端口被占了（v0.4.7）

服务经常不止精灵这一个入口——你可能在终端、IDE 里自己起过服务，nginx 也一直在后台托着站点。v0.4.7 起精灵能把"已经在跑"的看出来：

### 10.1 列表里的蓝 ○（外部运行）

| 状态点 | 意思 |
|---|---|
| 绿 ● | **精灵启动的**进程正在跑（点「停止」能停掉的） |
| 蓝 ○ | **外部运行**：这个项目的端口正在被监听，但进程不是精灵起的——多半是你自己在别处启动的；Nginx_ 站点亮蓝 = nginx 正在服务它 |
| 灰 ▪ | 没在跑 |

工具栏右侧会显示 `运行中: 2（外部 3）`。蓝 ○ 的项目详情卡片写明监听者，两种措辞：

- **"由本项目进程监听（node.exe pid=6616，外部启动）"**——精灵查到了监听进程的工作目录就在这个项目里，**确证**是它；
- **"在监听（xxx.exe pid=N，进程路径不可读，按端口推断）"**——进程是系统级的读不到路径，只能按端口猜，仅供参考。

为什么不多做一步确证就乱亮？因为**同一个端口常被多个项目声明**（比如所有 Vite 项目都默认 5173），只看端口的话一个监听者能把几十个项目全点亮。所以精灵宁可"查得到才亮"：查不到归属的端口只算"被占用"，不算"在运行"。

状态点靠**后台轮询**保持新鲜：默认每 2 秒看一次进程存活与端口监听（v0.4.17 起可在**设置 → 状态刷新**里改间隔 1~60 秒，或整体关掉自动刷新——关掉后列表仍有启动/重扫完成时的一次性状态快照，只是不再自己动）。机器上项目多、觉得轮询费电的话，把间隔调大即可；保存立即生效，不用重启精灵。

### 10.2 端口总览：全机端口被谁占着一屏看完

工具栏「📶 端口总览」：本机**所有**正在监听的端口列成表——端口、监听地址（127.0.0.1 = 只有本机能访问，0.0.0.0 = 局域网也能）、进程名、PID、归属哪个项目/启动项、是不是精灵管理的。默认 2 秒自动刷新。想清某个端口被谁占了、或者怀疑端口冲突时，看这里最快（进程名 + PID 直接拿去任务管理器定位）。

### 10.3 外部项目怎么停：与精灵启动的项目"稍作区别"

| | 绿 ●（精灵启动的） | 蓝 ○（外部运行的） |
|---|---|---|
| 按钮 | 「停止」——直接停，不弹确认（精灵知道自己在停什么） | 「结束进程」——先弹确认框（写明进程名/PID、提醒未保存数据会丢），确定后才结束 |
| 停的方式 | 停登记在册的进程树，杀完验证端口释放 | 同样树杀监听进程并复核端口，但对象是你自己起的进程，所以多一道确认 |
| 什么时候没有这个按钮 | — | 只在**确证**命中（查到了监听进程就属于这个项目）时才有；"按端口推断"和 nginx 合成站点不提供 |

为什么推断命中不给结束？推断意味着"只知道这个端口有人监听、不知道是不是这个项目"——此时按 PID 动手，杀错无关程序（甚至系统服务）的风险太高。想清理这种端口，去「端口总览」看清楚进程名/PID，再到任务管理器自行处理。

工具栏的「全部停止」只停精灵启动的项目，不会批量结束外部进程——外部进程一律单项目、单确认地结束。



## 11. 界面语言切换（v0.4.10）

设置里「界面语言」可切 **简体中文 / English**（写在 `profiles.json` 的 `settings.language`）。保存时若语言变了会问"重启后生效，现在重启吗？"，点确认精灵自动重启并直接以新语言出现——界面是启动时按语言一次性构建的，所以走重启而不是热切换。

几条设计决定，说明"为什么这样"：

- **英文作键、缺键落英文**：界面源字符串直接用英文，每种语言一份"英文→译文"词典。任何一处没翻到，英文界面显示英文原文——而不是退回中文，国际用户永远能读懂；简体中文界面会不会漏中文？selftest 的 `check_i18n` 不变量把源码里全部 `tr()` 字面量收干净，缺一条词条测试直接失败，漏不了。
- **天生多语言**：语言注册表驱动（代码 + 本语言显示名）。想加第三种语言 = 注册表加一行 + 新增一个词典，代码零改动。
- **缓存里的历史数据不翻译**：扫描结果缓存的启动项标签/类型仍是原存储值（重扫不冲、换语言不混），只在显示时映射——英文界面看到 "Frontend dev server"，中文界面看到 "前端开发服务器"，指向同一份缓存。
- **两种界面都能搜**：搜索索引里类型/标签中英两套都在，中文界面搜 "前端"、英文界面搜 "frontend" 都命中。

## 12. Docker 容器：看得见关联，管得了启停（v0.4.15）

有些服务不住在项目目录里，而是跑在 Docker 容器中（nginx 托管前端、ONLYOFFICE、数据库……）。精灵此前对它们完全失明——容器挂载的 nginx 配置在 Windows 进程表里根本看不见。v0.4.15 起精灵会问 Docker 本人（`docker ps` / `docker inspect`），把容器与项目、与 nginx 配置的关系摆出来。

### 12.1 你会看到什么

| 场景 | 展示 |
|---|---|
| 项目目录（或其子目录）被挂进某容器 | 详情页「Docker 容器关联」：`项目目录挂载进容器 oo（运行中）（项目内 dist/）`——这是**确证**关联 |
| 容器发布的端口与项目端口相同 | `端口 10100 与容器 oo 的发布端口相同——可能关联（运行中）`——按端口推测，措辞如此；服务真在跑时，启动项卡片也会写「端口 10100 由 Docker 容器 oo 发布」 |
| nginx 配置被容器挂载 | 详情页 nginx 区配置行标注 `容器 oo（运行中 · 扫描时）`——这份配置确实"在用"；引擎在跑却没有任何容器挂载它时，标注 `扫描时未发现挂载它的容器（可能未在用）` |
| 引擎没开 | 列表右键出现「启动 Docker Desktop」——点它，精灵拉起 Docker Desktop 并等引擎就绪（最长 90 秒），就绪后自动重扫 |

容器名/镜像名可以搜索（搜索框输入 `oo` 也能找到关联项目）。

### 12.2 启停：只动"关联到的"

- **入口**：项目行/站点行/引用行右键「启动容器 · oo」「停止容器 · oo」，或详情页 Docker 区每行的按钮（运行中→停止容器，否则→启动容器）。
- **与精灵「停止」的区别**：容器是 Docker 自己管的状态——**停止会弹确认**（其中的服务会不可达），启动不弹；执行走后台线程，完成后状态就地刷新，不用重扫。
- **为什么只动关联到的容器**：精灵只对"看得见关系"的容器负责；你机器上其他容器（别人部署的、系统依赖的）精灵绝不批量碰。「全部停止」也只停精灵启动的进程，不含容器。
- **边界不变**：容器里的 nginx 进程本身精灵仍不管理（v0.4.2 的约定）——启停容器 = `docker start/stop`，不是杀进程。容器发布端口上的监听者是 Docker 的端口转发进程，精灵永远不会对它给「结束进程」（杀了只断端口发布，容器还在跑）。

### 12.3 状态是"扫描时"的

容器状态标注都注明「扫描时」；启停操作完成后精灵会就地更新那一个容器的状态，其余容器的最新状态以重新扫描为准（F5）。引擎没开时精灵**不猜**——保留上次扫描的关联，扫描日志记一行，等你把 Docker 拉起来再扫。

## 13. 便携环境：带着环境一起搬家（v0.4.21）

精灵自己拷走即用，但项目要的工具（Node、JDK、Maven……）不在精灵身上——把工作区拷到一台没装这些工具的电脑，项目就起不来。设置里的「便携环境」区块解决这个问题：把便携版环境的目录填进去，精灵启动项目时会**先到这些目录找工具，找不到才用系统 PATH**。

### 13.1 怎么配

设置 → 「便携环境」→ 每行填一个目录（或点「添加目录…」选目录）。这些放法都能认出来（子目录嵌到三层、每层的 `bin` 子目录也搜；v0.4.22）：

| 你的目录长这样 | 命中方式 |
|---|---|
| 便携 Node 目录（里面直接有 `node.exe`/`npm.cmd`） | 目录本身 |
| 整包目录（里面 `node\`、`jdk-17\`、`maven\` 并排） | 一级子目录 |
| Tool_PortableEnvironment 整包根直填（工具在 `runtime\node`、`runtime\python`） | 二级子目录 |
| JDK 槽位（`runtime\java\<任意名>\bin\java.exe`，JDK 名字随意） | 三级子目录的 `bin` |

留空 = 一切照旧，只用系统 PATH。

### 13.2 生效范围

- **解析**：启动前的依赖预检和实际启动都先查便携目录——机器上没装 Node 也能起 Vite 项目；机器上装了也**优先用便携版**。
- **整条启动链**：子进程的 PATH 会把便携目录排在最前面，`npm run dev` 派生出的 node/vite、脚本里裸调的 `java` 都能找到；检出便携 JDK 时还会设 `JAVA_HOME`（gradle/mvn 需要）。
- **搬家用法**：相对路径（如 `portable\node`）以**精灵所在目录**为锚——精灵连同 `portable\` 文件夹一起拷到新电脑，什么都不用改。写绝对路径、`%VAR%` 也行。
- **不生效的场合**：静态页/内置服务不起进程，用不上；配置只认目录不认单个文件；`.cmd` 里写死的绝对路径（项目自己的脚本指向旧机器路径）不归便携环境管——那是启动方式编辑的事。

### 13.3 与 Tool_PortableEnvironment 的配合

便携环境包项目（Tool_PortableEnvironment）已就绪：设置里把它的目录填进来即可——**整包根直填**（`Tool_PortableEnvironment`）或填到 `runtime` 这级都行，Node/Python 即刻命中；之后往 `runtime\java\` 放进 zip 版 JDK（不用改名），精灵也会自动识别并设好 `JAVA_HOME`（v0.4.22）。`env.bat`/`start_spirit.bat` 那条 PATH 注入通路与此并存不冲突：只用精灵配置式的话，**不再要求必须从 `start_spirit.bat` 启动**，双击精灵 exe 也生效。

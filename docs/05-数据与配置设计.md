# 05 · 数据与配置设计

> 一句话原则：**所有状态写在 exe 旁边，一个文件夹拷走就是全部**。

## 1. 文件布局（便携铁律）

```
任意目录/
├── 项目启动精灵.exe
├── profiles.json      ← 用户档案：覆盖、收藏、设置（随 exe 走）
├── scan_cache.json    ← 扫描缓存（可删，删了就重扫）
└── logs/
    ├── Tool_ChoiceKit_20260921_1.log
    ├── G_LevelForge_20260921_1.log
    └── …
```

便携铁律（实现时的硬约束）：

1. **不写注册表**、**不写 AppData/LocalAppData**、不写家目录。
2. 所有路径以"exe 所在目录"为锚点解析（`sys.executable` 的目录，而非 `cwd`——用户从别处双击时 cwd 不可靠）。
3. 配置文件用**原子写**：先写 `*.tmp` 再 `os.replace`，断电不产生半截文件。
4. 全部 UTF-8 无 BOM，JSON 缩进 2 格，人可手改（手改冲突处理见 §4）。
5. 删掉 `scan_cache.json` 与 `logs/` 不损失任何用户决策——只有 `profiles.json` 是需要备份的。

**边界（v0.4.6）**：端口防火墙功能写入的规则是 **Windows 防火墙（系统级状态）**，不属于便携铁律管辖——铁律约束的是精灵自身的数据文件（精灵写规则只产生即用即删的临时 ps1/结果文件）。规则可随主机保留，拷贝精灵到新机后规则不会跟过去，按需重写或在总设置里清理。

字段语义与合并规则：

| 字段 | 语义 |
|---|---|
| `projects.{name}.entries[].locked` | **true = 用户改过**，重扫时原样保留；false = 仅检测结果缓存，重扫会被替换 |
| `disabled` | 保留定义但列表隐藏（临时停用某启动项） |
| `port_knowledge` | "项目 → 惯用端口"学习表：日志回读到新端口、embedded 服务分配过的端口都记在这 |
| `custom_projects` | 完全手工挂载的外部项目（不在扫描根下） |
| `recent` | 最近启动（v0.5 界面化），只留最近 30 条 |
| `settings.auto_scan_on_start` | v0.2：启动时是否自动扫描；false = 直接用 scan_cache 上次结果拼列表（不扫盘） |
| `settings.console_mode` | v0.4：`integrated`=捕获输出进精灵运行窗（默认）；`windows`=各项目弹原始控制台（不捕获、无法端口回读） |
| `projects.{name}.group` | v0.2 用户分组名；v0.4.4 起三档语义（docs/02 §8.5）：非空且非 `"-"` = 手工分组（最优先）；`""` = 未设 → 自动按父文件夹（= 扫描根）分组，仅 nginx 合成站点按来源 nginx 分 `nginx(配置路径)` 组（v0.4.5，不受退化平铺影响），全部待自动分组项目来自同一父文件夹时退化平铺；`"-"` = 保留哨兵，显式不分组。分组列表由现存值推导，无独立配置段 |
| `projects.{name}.name_cn` / `name_en` | v0.2 手工标注的中/英文名；显示优先级：name_cn ＞ name_en ＞ 扫描猜测 ＞ 目录名 |
| `projects.{name}.logo` | v0.2 手工指定的 logo；""=用自动发现的；项目内路径存相对、项目外存绝对 |
| `order` | v0.2.2 手动排序：groups=分组行顺序；projects=项目平铺顺序基准（组内序与未分组序从中派生）。未列出的条目排已列出者之后、按名称序兜底；含已消失项目的残留条目无副作用 |
| `projects.{name}.log_to_file` | v0.2.4 控制台日志落盘开关，默认 false。true = 该项目捕获型输出只写日志文件（`log_dir` 指定目录，空 = 精灵旁 logs/），公共"运行日志"不滚动其内容、仅留一行路径提示；端口回读不受影响 |
| `projects.{name}.log_dir` | v0.2.4 该项目日志目录，"" = 默认 logs/；不存在则启动时创建 |
| `projects.{name}.log_retention_days` | v0.2.4 日志保留天数，默认 365，0 = 永不清理。**清理是手动动作**：工具栏"🧹 清理旧日志"按钮点击时才全量扫描各项目日志目录，按**文件名内时间戳**判定超过保留期的文件（含 1MB 轮转分卷）删除；启动时零扫描；任何非标准命名（非 `{项目}_{yyyyMMdd_HHmmss}.log`）的文件永不触碰 |
| `settings.scan_nginx` | v0.4.2：是否扫描系统 nginx 配置并关联项目（docs/02 §9）。false = 清空全部关联与站点 |
| `settings.nginx_conf` | v0.4.2：手动指定 nginx.conf（文件或目录）；v0.4.7 起**可多个，以换行分隔（每行一个）**，有效份全部解析；"" = 自动探测（可发现多份，全部解析）；部分无效忽略无效份并在扫描日志列明，**全部无效不回落自动**，扫描日志提示 |
| `settings.nginx_show_only` | v0.4.2：是否列出仅 nginx 引用的站点（`Nginx_` 前缀合成项目，static 启动项=打开访问地址）。关掉只隐藏 N3 站点，N1/N2 项目关联保留 |
| `settings.scan_docker` | v0.4.15：扫描 Docker 容器并关联项目（docs/02 §10 D 系规则：D1 conf 挂载 / D2 端口发布 / D3 目录挂载）。false = 清空全部容器关联；引擎 off/down 时不写不删（保留上次结果），只记扫描日志。容器状态是 Docker daemon 的系统状态，**不随 profiles 走**，本键只存开关 |
| `settings.nginx_show_possible` | v0.4.16：是否显示 nginx 分组里**仅按端口推测**的引用行（N2 proxy-only，"可能关联"）。默认 false = 不显示（同端口撞车的项目拷贝噪音大）；`group_refs(include_possible=False)` 纯函数滤除，host+proxy 混合行不受影响，滤空的配置整组不出现；true = 恢复 v0.4.8 全量显示 |
| `settings.status_poll_enabled` | v0.4.17：主窗口运行状态**自动刷新**开关（绿●/灰○/蓝○ 状态点 + 外部运行感知的 2 秒周期轮询）。false = 不再周期轮询（启动/重扫完成时的一次性状态快照保留）；「端口总览」对话框的自动刷新有自己独立的开关，不受本键影响 |
| `settings.status_poll_seconds` | v0.4.17：运行状态轮询间隔（秒）。默认 2；写入与读取都经 `profiles.normalize_poll_seconds` 归一（垃圾值回落 2，clamp 1~3600），设置对话框 Spinbox 限 1~60；保存后经 `on_poll_changed` 回调立即重排定时器，无需重启 |
| `settings.nginx_excluded` | v0.4.9：排除的 nginx.conf，**以换行分隔（每行一个）**，容忍引号/空白行、去重保序；normcase 归一后**整路径精确比对**（不做目录前缀匹配）；不校验存在性（指向已删文件的条目可保留）。被排除配置不参与关联扫描（手动指定的同样生效，排除优先），扫描日志注明；空串 = 不排除 |
| `settings.language` | v0.4.10：界面语言，取值 `core/i18n.LANGUAGES` 注册表内的代码（`zh-CN`/`en`），默认 `zh-CN`；读取处 `.get("language", "zh-CN")` 兜底，旧 profiles.json 缺键零迁移。改值保存后由设置对话框询问重启生效；非法值按缺键处理（回落 zh-CN，界面缺翻译回落英文） |
| `settings.portable_env` | v0.4.21：**便携环境目录**，以换行分隔（每行一个）——随精灵拷到别的电脑时指向便携 Node/JDK/Maven 等环境根。启动/预检时这些目录**先于系统 PATH** 解析依赖（docs/03 §3.4 v0.4.21 段），子进程 PATH 前置并按需设 `JAVA_HOME`。容忍引号/空白行、去重保序；支持 `%VAR%`/`~` 展开；**相对路径以精灵所在目录为锚**（便携铁律——精灵目录旁的 `portable\node` 换机不失效，故原样存储、解析时才展开）；不校验存在性（未插的 U 盘条目可保留）；`""` = 不启用，只用系统 PATH |
| `projects.{name}.firewall` | v0.4.6 端口防火墙的**意图记忆**：上次成功写入系统防火墙的端口/协议（tcp/udp）/远程范围（`localsubnet`/`any`/自定义值）/配置文件（netsh profile 值），仅用于「端口防火墙」对话框预填。**真实规则在系统防火墙里，不随 profiles 走**（换机后需重写）；「删除本项目规则」成功后清空；"恢复自动检测"保留 |
| `version` | schema 版本号，升级时做迁移函数 |

v0.2 起这些用户标注（group/name_cn/name_en/logo/favorite）在"恢复自动检测"时**保留**——只清启动项覆盖；v0.2.4 起 log_to_file/log_dir/log_retention_days 同样保留（用户偏好，非检测值）。

**v0.4.4 身份键**：`projects` / `order.projects` / 日志文件名都以**身份键**索引——默认 = 项目目录名；跨扫描根出现同名项目时，按 `scan_roots` 顺序首个保留裸名、后续项为「根名/项目名」（如 `WS乙/Tool_X`，日志文件名安全化为 `WS乙_Tool_X`）。无重名时与旧版键完全一致，**profiles.json 与 scan_cache.json 均零迁移**。已知限制见 docs/02 §8.5（端口知识库按裸名共享等）。

**合并顺序（effective 视图）**：`locked/自定义项` ＞ `检测项`，再经 `disabled` 过滤。与 docs/02 §5 一致：检测只是建议，人改过的永远赢。

## 3. scan_cache.json · 扫描缓存

```json
{
  "Tool_ChoiceKit": {
    "mtime": 1790000000.123,
    "detected": { "nginx": [] }
  },
  "@nginx": {
    "sites": [
      { "name": "Nginx_portal-ui", "path": "/mnt/software/portal-ui/dist",
        "project_type": "Nginx", "entries": ["…static 启动项…"],
        "nginx": ["…site 关联…"] }
    ]
  }
}
```

- 键 = 身份键（v0.4.4：默认项目目录名；跨扫描根重名时为「根名/项目名」，docs/02 §8.5），`mtime` = 项目根与白名单子目录 mtime 的最大值。
- 重扫时 mtime 未变 → 直接用缓存的 `detected`（LaunchEntry 原样序列化）；变了 → 重跑 detector，替换其中**未锁定**的项。
- v0.2 起 `detected` 里增加 `guessed_name` / `logo`（docs/02 §8 的扫描猜测与 logo 发现结果）；**旧缓存缺这两个键 = 视为过期**，自动重检一次补齐。
- v0.4.2 起 `detected.nginx` = 该项目的 nginx 关联列表（N1/N2，docs/02 §9）；`"@nginx"` 键存 N3 仅 nginx 站点（合成项目完整序列化）。两者**每次扫描全量重算覆盖**（nginx.conf 是系统级文件，不随项目 mtime 缓存）；自动扫描关闭时 `_load_from_cache` 从这两个位置恢复。
- v0.4.15 起 `detected.docker` = 该项目的容器关联（D2/D3，docs/02 §10）；`"@docker"` 键存引擎态/容器态/conf 归属/发布端口快照。docker CLI 只在扫描 worker 线程调用；引擎 off/down 时**不写不删**（保留上次结果）；容器启停成功后 GUI 就地改写内存与缓存里的状态，免整轮重扫。
- "重新扫描"按钮默认走缓存；按住 Shift 点 = 强制全量重检（应对文件内容变了但 mtime 没变的边角情况）。
- 自动扫描关闭时启动：直接读缓存拼列表（只 stat 目录存在性，不读项目内容）。

## 4. 与外部手改的冲突

用户在精灵开着时手改 `profiles.json`：

- v0 策略：精灵**只在自身有变更时写入**，不周期回写；保存前若发现磁盘 mtime 比内存新，弹"配置文件在外部被修改：[用磁盘版] [用我的内存版]"。
- 简单、够用；不做文件监听（watchdog 是第三方依赖，违背依赖纪律）。

## 5. 日志文件

| 规则 | 值 |
|---|---|
| 位置 | `logs/{项目安全名}_{yyyymmdd}_{序号}.log` |
| 项目安全名 | 目录名里 `\/:*?"<>|` 替换为 `_`（中文保留） |
| 编码 | UTF-8 无 BOM，行缓冲追加 |
| 轮转 | 单文件 1MB，每项目保留最近 3 个 |
| 内容 | 首行元数据（命令、cwd、PID、开始时间）+ 子进程原始输出 + 精灵事件行 |
| GUI | 底部日志区实时 tail（订阅推送，不轮询读文件） |

`[精灵]` 事件行示例（排障的全部线索）：

```
[精灵] 2026-09-21 12:01:03 启动: node tools/server.js 8787 (pid=23116)
[精灵] 2026-09-21 12:01:04 日志回读端口: 8787 → 打开 http://localhost:8787
[精灵] 2026-09-21 12:40:11 停止请求: taskkill /PID 23116 /T /F → 端口 8787 已释放 ✓
```

## 6. 备份与迁移

- **备份** = 复制 `profiles.json`（一切用户决策都在里面）。
- **迁移到新机** = 整个文件夹拷走；路径失效的项目在列表标"路径不存在"，右键改路径或删掉。
- 精灵自身无自更新（v2 议）：更新 = 换 exe，配置原地不动。

## 2. 列表行与状态色

| 状态点 | 含义 | 触发 |
|---|---|---|
| 灰 ▪ | 未运行 / 不可启动（文档型整行灰显） | 默认 |
| 黄 ● | 启动中（spawn 后健康检查未过，v1） | 启动瞬间 |
| 绿 ● | 运行中（进程存活 / embedded 服务在线）——**精灵启动的** | 2 秒轮询 |
| 蓝 ○ | **外部运行**（v0.4.7）：端口在监听但不是精灵启动的——自己在终端/IDE 里起的服务、或 nginx/docker 正在服务该站点。判定：监听进程 cwd/exe 落在项目目录内 = 确证；进程路径读不到 = 按端口推断（详情卡片措辞标明）；路径可读但不属于任何项目 = 只是端口被占，不算。合成 nginx 站点恒按端口推断。确证命中的提供「结束进程」（弹确认后树杀）；推断命中的只展示 | 2 秒轮询 |
| 红 ● | 失败/已停止但有错误 | 预检失败、异常退出 |

工具栏右侧计数同步显示外部量：`运行中: 2（外部 3）`。「📶 端口总览」按钮（v0.4.7）看本机全部监听端口与归属（docs/04 §4.8）。容器发布端口（v0.4.15）在蓝 ○ 备注里直接写明：「端口 10100 由 Docker 容器 oo 发布（镜像）」——监听者是 docker backend，**永不给「结束进程」**（杀它只断端口发布、容器照跑；启停请用容器菜单）。

**轮询节奏（v0.4.17）**：状态轮询默认 2 秒，可在设置「状态刷新」区块改间隔（1~60 秒）或整体关闭（`settings.status_poll_enabled` / `status_poll_seconds`，保存立即生效无需重启）。关闭后不再周期刷新，但启动/重扫完成时仍做一次状态快照（列表有初始状态点）；「端口总览」的自动刷新有自己的独立开关，不受影响。

类型小标签（文字即可，不追求图标）：`静态` `PWA` `Node` `Java` `Python` `组合` `游戏` `文档` `未识别`，v0.4.2 新增 `Nginx`（仅 nginx 引用的合成站点，端口列显示其 listen）。组合项目显示启动项数（如"组合 2"）。

**组合类型（v0.4.14）**：列表类型列恒为单类型（按项目类型优先级取一，如混栈项目 `Java ·2`）；**详情页副标题**用 `detector.type_mix` 把技术栈类型全部列出——`Java+Node（规则 R3/R4）`；R1 辅助脚本与 R12 打包成品不算栈（单栈项目显示不变），空/纯非栈回落单类型；组合类型（原始值 + 显示名）进搜索素材。

**名称/路径可选中复制（v0.4.19）**：详情页头部的显示名、副标题（`类型（规则）· 端口 · 目录 文件夹名`）与完整路径行用扁平只读 Entry 渲染（`app/widgets.selectable_entry`）——外观同 Label，但可像文本一样拖选、双击选词、三击/Ctrl+A 全选、Ctrl+C 复制；路径行「打开目录」改为**双击**触发（单击让位给选中文本），悬停有提示。

v0.2 行内容：**项目列** = 文件夹名（定死不猜）；**名称列** = 用户标注（`中文名 · 英文名`）＞ 猜测的中/英拆分 ＞ 猜测原文（docs/02 §8；与目录名相同才留空）；**端口列** = 该项目全部启动项的去重端口（如 `5173, 8080`）；有显著 logo 时行首显示 18px 小图（识别规则见 docs/02 §8.2，无 logo 不留占位）。分组行显示 `分组名（N）`，可折叠，双击切换展开。

**nginx 引用行（v0.4.8，docs/02 §9.5）**：nginx 分组内项目行之后、`↗ 身份键` 形态的交叉引用行（type 列 `已关联 · 托管/反代`），把被真实项目"认领"走的 nginx 关联（N1/N2）也在分组里列出来——只有引用行没有站点的配置（如在用的 Windows 裸装 nginx）由此获得可见分组。状态点/前景色跟随目标项目当前状态；不可启动、不可拖动。

排序（v0.2.2 定稿）：

- **手动序是默认状态**：顺序存 `profiles.order`（groups=分组行顺序，projects=项目平铺序，组内/未分组序从中派生），重启保留；未排过的项目按名称序兜底。
- **拖动**：项目行拖到项目行上=排到它前面（跨组则入它的组）；拖到分组行上=入该组末尾；放开在空白处=当前层级末尾；分组行拖到分组行/分组内项目上=调整分组顺序。搜索过滤中拖动被阻断。
- **右键**：项目行/分组行都有「排序 → 上移/下移」（分组行另有折叠/展开）；列排序视图下另有「恢复手动排序」。
- **列头点击三态**：升（▴）→ 降（▾）→ 回到手动序（无箭头）；列排序下分组随方向正/反排；名称/端口列"无值沉底"。
- 列排序视图下发起拖动会自动切回手动序再执行。

| 「访问」按钮（v0.4） | 启动项卡片上有 URL 即显示：用设置浏览器打开该地址，与启动无关（服务已在跑/只想起页面） |
| 「端口防火墙…」（v0.4.6） | 详情操作区 + 右键菜单：打开单项目防火墙对话框（docs/04 §4.7），把项目端口写入 Windows 防火墙入站允许，局域网/远程可访问 |
| 「🛡 防火墙总设置」（v0.4.6） | 工具栏按钮：打开全机精灵防火墙规则总览（查看/启停/删除，docs/04 §4.7） |
| 「📶 端口总览」（v0.4.7） | 工具栏按钮：本机全部监听端口 × 项目归属总览（docs/04 §4.8） |
| 「启动容器/停止容器 · X」（v0.4.15） | 项目行/Nginx_ 站点行/nginx 引用行右键 + 详情页 Docker 区每行的上下文按钮：启停**关联到的**容器（D1 conf 挂载 / D2 端口发布 / D3 目录挂载，docs/02 §10）。停止弹确认（容器内服务会不可达）；后台线程执行 docker start/stop，完成就地回写状态免重扫；引擎级失败转「现在启动 Docker Desktop 吗？」 |
| 「启动 Docker Desktop」（v0.4.15） | 引擎未运行（off/down）时替代容器启停项出现；拉起 Docker Desktop 后后台等待引擎就绪 ≤90 秒，就绪自动重扫 |
| 外部运行的启动项卡片（v0.4.7） | 蓝字说明实际监听者："端口 5173 由本项目进程监听（node.exe pid=6616，外部启动）"（确证）或"端口 X 在监听（xxx.exe pid=N，进程路径不可读，按端口推断）"。**确证命中**的按钮与菜单项是**「结束进程」**——与精灵「停止」区分：弹确认框（写明进程/pid、未保存数据会丢）→ 树杀监听进程（taskkill /T）→ 杀后复核端口释放并写运行日志；**推断命中不给结束**（按端口乱杀可能误伤无关进程），nginx 合成站点同样不给（精灵不管理 nginx/docker 进程） |
| Nginx 关联区（v0.4.2） | 详情页启动项下方：托管前端（`nginx 托管前端：http://localhost:9003/`）/ 被反代（`被 nginx :18080 /webdocs/dataApi/ 反代 → 本项目端口 28080`）/ 站点，每条带 [访问]；细节行显示 root（本机路径/项目内子目录/容器路径三态）与反代后端；底部配置文件路径可点击打开。站点类合成项目（`Nginx_` 前缀）的启动按钮 = 打开访问地址（static 语义），精灵不管理 nginx 进程 |
| Docker 容器关联区（v0.4.15） | 详情页 nginx 区下方（有 D2/D3 关联才显示）：D3 挂载=确证「项目目录挂载进容器 X（状态）（项目内 dist/）」、D2 端口=可能「端口 P 与容器 X 的发布端口相同——可能关联（状态）」，灰字附镜像名；每行带 启动容器/停止容器 按钮（引擎在跑时）。nginx 区配置文件行追加容器归属：「容器 X（状态 · 扫描时）」或「扫描时未发现挂载它的容器（可能未在用）」 |
| 双击 nginx 引用行（v0.4.8） | 跳转：列表定位选中目标项目行并打开其详情（目标被搜索过滤隐藏时先清空搜索词再定位） |
| 右键 nginx 引用行（v0.4.8） | 菜单：打开访问地址（该配置下该项目的全部 nginx 地址，多条逐列）/ 跳转到项目 / 打开配置文件 |
| F5 | 重新扫描 |
| Ctrl+F | 聚焦搜索 |
| Enter（列表聚焦时） | 启动选中项 |
| Esc | 清空搜索 |

## 4. 关键对话框

### 4.1 编辑启动方式（对应 docs/02 §5 覆盖机制）

```
┌─ 编辑启动方式 ─ Tool_ChoiceKit ────────────────────┐
│ 启动项: 选择器服务            [恢复自动检测]               │
│ 标签     [选择器服务______]                               │
│ 类型     (●)持续服务  ( )应用  ( )静态页  ( )内置服务  ( )脚本│
│ 命令     [node] [tools/server.js] [8787]   ← 逐参数分格   │
│ 工作目录 [（项目根）____________]                          │
│ 端口     [8787]   打开地址 [http://localhost:8787]        │
│ ☑ 启动后自动打开浏览器   ☐ 显示控制台窗口                  │
│ ☑ 锁定此配置（重扫不覆盖）                                 │
│                          [取消]  [保存]                   │
└──────────────────────────────────────────────────────────┘
```

- 保存即写 `profiles.json` 并置 `locked=true`。
- "命令"按空格拆参数逐格编辑，避免引号地狱；高级用户可切"整行编辑"模式。

### 4.6 清理旧日志（v0.2.4 · 手动按钮）

工具栏【🧹 清理旧日志】：点击才全量扫描各项目日志目录（启动时零扫描开销）→ 汇总确认"将删除 N 个超过保留期的文件（约 X MB）"→ 删除并汇报。判定按**文件名内时间戳**与各项目 `log_retention_days`（默认 365，0=该项目跳过）；只动严格标准命名的日志文件与其分卷，任何其他文件（手动复制、其他命名）永不触碰。运行日志页顶部另有【仅看选中项目】过滤与【清空显示】按钮——被过滤的行不进 Text 控件不占内存，全量始终在日志文件里。

### 4.7 端口防火墙 / 防火墙总设置（v0.4.6）

服务在本机跑起来了，别的机器访问不到——多半是防火墙拦了入站。v0.4.6 把"开端口"做成精灵的一等操作，数据层见 docs/03 §3.10。

**端口防火墙（单项目）**：详情操作区「端口防火墙…」或右键菜单打开。

```
┌─ 端口防火墙 · Tool_ChoiceKit ──────────────────────┐
│ （说明：入站允许 + UAC 授权提示 + 只动精灵自己的规则）        │
│ 开放端口（入站允许）                                        │
│  ☑ 8787  ☑ 5173  ☐ …   手动添加端口 [____] [＋ 添加]        │
│ 协议     [TCP ▼]（TCP / UDP / TCP+UDP）                     │
│ 远程范围   [仅局域网（本地子网）▼]（/ 所有远程地址 / 自定义…）  │
│ 自定义     [192.168.1.0/24,10.0.0.5-10.0.0.20]（选"自定义"启用）│
│ 配置文件   [全部（域/专用/公用）▼]                            │
│ 本项目现有规则（系统实时）                                   │
│  启动精灵_Tool_ChoiceKit_8787_TCP  8787 TCP 本地子网 启用│
│              [写入 / 更新规则] [删除本项目规则] [关闭]        │
└──────────────────────────────────────────────────────────┘
```

- 端口候选 = 启动项检测 + 端口知识库 + 上次防火墙配置（profiles 意图记忆，预填）+ 系统现有规则，全部默认勾选；支持手动补端口（1~65535）。
- 远程范围默认**仅局域网（本地子网）**——最小暴露面；要公网可访问才选"所有远程地址"或自定义 IP/CIDR/范围。
- 「写入 / 更新规则」：勾选端口 × 协议逐条生成 `启动精灵_{项目}_{端口}_{协议}` 规则，一次 UAC 批量写入（add 前先删同名 = 幂等，可反复点）；「删除本项目规则」删掉本项目全部精灵规则并清意图记忆。
- 下方实时列出系统里本项目的精灵规则（读免管理员）；读取/写入都在后台线程，对话框不卡。

**防火墙总设置**：工具栏「🛡 防火墙总设置」打开，**只列由精灵写入的规则**（名称前缀 + description 标记双重识别，用户手工建的其他规则看不见也动不到）。

- 列：规则名 / 项目（description 归属）/ 端口 / 协议 / 方向 / 远程范围 / 配置文件 / 状态（启用/停用）。
- 操作：[启用·停用]（保留规则暂不生效）、[删除选中]、[全选]（配合删除 = 一键清空全部精灵规则）、[刷新]、[打开系统防火墙设置]（control firewall.cpl，看系统全量规则/高级设置）。
- 修改类操作打包成一次 UAC 授权批量执行；状态栏常驻提示当前管理员权限与授权行为。

### 4.8 端口总览（v0.4.7）

│ （说明：管理=精灵 的进程由精灵启动；其余为外部程序。          │

│ 5173  0.0.0.0    node.exe    6616  G_BlockWorld…  前端 dev   │

### 4.9 nginx 分组引用行（v0.4.8）

在用的 nginx 配置如果托管的是**工作区里的真实项目**（N1/N2），关联写进项目详情后列表里就没有它的踪影——本机 D 盘裸装 nginx 就是典型。v0.4.8 把这类关联也放进 nginx 分组：合成站点行之下追加**引用行**，与"仅 nginx 站点"一眼区分。

```
  ▾ nginx(F:\nginx.conf)（4）
      Nginx_portal-ui          站点访问（nginx :9090）   …  Nginx
      Nginx_admin-portal            站点访问（nginx :5173）   …  Nginx
      Nginx_onlyoffice      站点访问（nginx :18080）  …  Nginx
    ↗ P_CityTwin         ○   9090   已关联 · 反代
  ▾ nginx(D:\Program Files\nginx\conf\nginx.conf)（2）
    ↗ 202511_harbor          ▪   9003   已关联 · 托管
    ↗ 202606 Q7 web-…      ▪   18080  已关联 · 托管、反代
```

- 行文案：name 列 `　↗ {身份键}`（组内缩进同项目行），type 列 `已关联 · 托管/反代`（N1+N2 双角色并列）；状态点与前景色 = 目标项目当前状态（跳过去看到的一致）。
- 同一项目在同一配置下的多条关联**合并一行**（`ngxscan.group_refs` 纯函数，docs/02 §9.5）；只有引用行没有站点的配置照常建组（如上面的 D 盘组）。
- 交互：双击 = 定位目标项目行并打开详情（被搜索过滤时先清搜索）；右键 = 打开访问地址（多条逐列）/ 跳转到项目 / 打开配置文件；不可启动、不可拖动排序；组头计数含引用行，折叠/展开与组一致。
- 开关：跟随「扫描系统 nginx 配置」总开关；「列出仅在 nginx 里出现的站点」关闭后站点消失，引用行仍在（它不是"仅 nginx 站点"）。

## 5. 视觉与可用性原则

1. tk 原生控件 + 系统字体（微软雅黑 10pt），不引皮肤库——单 exe 体积优先。
2. 状态点用字符（●▪）着色实现，不依赖图片资源；如加图标，放 `assets/` 一并打包。
3. 列表几百行不卡：`ttk.Treeview` + 只在选中时渲染右侧详情。
4. 长路径显示截断加 `…`，悬停/复制按钮拿全路径。
5. 窗口标题栏显示运行中数量，最小化到任务栏（v0 不进托盘）。

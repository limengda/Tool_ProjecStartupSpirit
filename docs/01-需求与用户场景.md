# 01 · 需求与用户场景

> 本文档定义项目启动精灵"为什么做、给谁用、做到什么程度算好"。

## 1. 背景与痛点

用户的工作区 `F:\Workspace\Space_Zcode` 目前有 **28 个真实项目**（不含本工具），按前缀分为 Tool_（工具）、G_（游戏）、P_（正式项目）、Book_、Doc_、Think_、Video_。盘点（2026-09-21）显示启动方式高度碎片化：

| 启动方式 | 项目数 | 典型例子 |
|---|---|---|
| 双击 bat/ps1 脚本 | 5 | `G_LevelForge/start.bat`、`Tool_NodeCanvas/启动ComfyUI工具.bat`、`Tool_TaskPlanner/启动.bat` |
| 前后端两个进程（Maven + npm） | 4 | P_CityTwin、P_FactoryFlow、P_FactoryFlow_G、P_MobileLabNotes |
| node 起服务 | 3 | Tool_ChoiceKit（`node tools/server.js 8787`）、G_MythicJourney ×2（`node serve.js`） |
| Python 脚本/GUI | 5 | G_NovaPlayer、Tool_ProcessPortManger（.pyw）、Tool_DataAudit 等 |
| 直接开 index.html | 4 | Book_MoonEssays、Book_RiverNotes、Tool_MiniGen（多个子页面） |
| 桌面程序/成品 | 2 | Tool_PromptKit（单 jar）、G_ImmortalPath（Godot 成品 exe） |
| 纯文档无需启动 | 5 | Doc_CityTwinDocs、Think_*、G_UnityRealmRPG 等 |

具体痛点：

1. **记不住**。28 个项目至少 7 种启动姿势，过两周回来就忘了"这个是双击 bat 还是 npm run dev"。
2. **端口撞车**。5173 被 4 个 Vite 前端共用，8080 被 3 个 Spring Boot 后端共用，8931 被 2 个 serve.js 共用；并行启动两个项目就有一个起不来。Tool_NodeCanvas 已经自带"被占自动顺延 28189…"的补丁，说明这个问题真实发生过。
3. **前后端要开两个**。P_ 系列项目必须先起后端再起前端，两个终端窗口手动切目录敲命令。
4. **黑窗难管**。服务起来后是一排控制台窗口，分不清谁是谁；直接关窗有时杀不干净子进程（node 服务残留占用端口）。
5. **新机冷启动**。换电脑/重装后，要重新回忆每个项目怎么跑。

## 2. 目标用户

**单人使用**（作者本人）。因此设计中**不需要**：多用户、权限、云端同步、协作功能。需要的是：中文界面、大按钮、双击为主、少配置。

## 3. 用户场景故事（v0 ~ v1 范围）

### S1 · 扫描总览
我打开精灵，它自动扫描 `F:\Workspace\Space_Zcode`，左侧列出全部 28 个项目，每个带类型图标（网页/Node/Java/Python/文档/游戏）和一个状态点（灰=未运行）。文档型项目也列出来，只是标灰显示"无需启动"。顶部有搜索框，输"nodecanvas"立刻过滤。

### S2 · 一键启动
我想看选择器。双击列表里的 Tool_ChoiceKit → 精灵按检测到的命令 `node tools/server.js 8787` 启动 → 浏览器自动打开 `http://localhost:8787` → 状态点变绿，日志区开始滚动服务输出。全程我不需要记任何命令。

### S3 · 项目自带启动脚本的，尊重项目
双击 Tool_NodeCanvas → 精灵发现它有自己的 `启动ComfyUI工具.bat`，直接执行这个 bat（不自己拼命令），日志照常被精灵捕获。项目入口的既有逻辑（如端口顺延）原样生效。

### S4 · 端口冲突提示
我同时启动两个 Vite 前端。第二个启动前，精灵预检 5173 端口发现被占：弹提示"5173 已被 P_CityTwin 前端占用"，让我选【仍要启动（Vite 会自动换端口）/ 取消】。启动后精灵从日志里读出实际端口，开对应的浏览器地址。

### S5 · 停止与重启
列表右键 Tool_ChoiceKit → 停止。精灵对进程树执行 `taskkill /T`（连同 node 的子进程一起杀干净），状态点变灰，日志里留下"已停止，运行 3 小时 12 分"。右键还有"重启"。

### S6 · 检测错了，改一次记住
精灵把 G_MythicJourney 识别成"纯静态，file:// 直开"，但它其实需要 `node serve.js`（nodecanvas-lab 页面要服务端）。我右键 → 编辑启动方式 → 把命令改成 `node serve.js`、端口 8931 → 保存到 profiles.json。以后每次扫描，这个项目都用我改的方式，检测不再覆盖我的决定。

### S7 · 拷走即用
我把精灵的 exe（连同旁边自动生成的 `profiles.json`、`logs/`）整个拷到 U 盘，插到另一台没有装 Python 的电脑，双击 exe 直接能用：配置还在、扫描重跑一遍即可。不写注册表、不进 AppData。

### S8 · 前后端组合一键
双击 P_CityTwin 的【一键启动前后端】：精灵先起后端（`mvn spring-boot:run`，8090），再起前端（`npm run dev`，5173），两个启动项各自状态、各自日志标签页。右键项目 → 全部停止，两个进程树都杀干净。

### S9 · 依赖缺失时给出人话提示
我在没装 Maven 的电脑上启动 P_ 系列后端。精灵预检 `mvn --version` 失败，不弹一堆 Java 堆栈，而是提示"未找到 mvn 命令，请安装 Maven 并加入 PATH"，启动项标红，其他启动项不受影响。

## 4. 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 通用进程/端口管理器 | 已有 Tool_ProcessPortManger（psutil + tkinter），不重复造轮子 |
| 包管理器 / 环境安装器 | 不负责装 Node/JDK/Python；只做**探测**和**提示**（v1） |
| `npm install` / `pip install` 自动执行 | v0 只检测 `node_modules` 缺失并提示；是否代跑安装由用户决定（v1 再议） |
| 远程主机启动、多机同步 | 单机单人工具 |
| 代码编辑、Git 集成 | 超出"启动"范畴 |
| 后台常驻系统托盘 | v2 再考虑；v0 就是一个普通窗口程序 |

## 5. v0 验收标准（草案）

实现完成后，逐条核对：

1. 对 28 个真实项目执行一次全量扫描，**检测规则预期表（docs/02 附录 A）的符合率 ≥ 90%**，且 P_ 系列 4 个前后端项目全部正确拆出"后端 + 前端"两个启动项。
2. 任选一个 bat 型项目（如 G_LevelForge）、一个 node 型（Tool_ChoiceKit）、一个静态型（Book_MoonEssays），双击启动成功：进程存活、（有端口的）浏览器自动打开、日志在窗口可见。
3. 停止任一运行中的启动项后，用 Tool_ProcessPortManger 验证：**对应端口已释放、无残留子进程**。
4. 并行启动两个共用 5173 的 Vite 前端，第二个启动时收到明确的冲突提示（而非静默失败）。
5. 在 profiles.json 中手工覆盖某项目启动命令后重扫，覆盖生效且不被检测结果冲掉。
6. PyInstaller 打包的单 exe 拷到无 Python 环境的干净目录，双击可运行、可扫描、可启动（docs/06 验收清单全过）。

## 6. 已知风险与开放问题

| # | 风险/问题 | 当前倾向 |
|---|---|---|
| 1 | bat 脚本内容五花八门，解析命令/端口的准确率有限 | 只提取"可提取的"（set PORT=、http.server、--port 等模式），提不到就整段执行 bat，不强行解析 |
| 2 | PyInstaller 单 exe 首次启动解包慢（约 2~5 秒白等） | 接受；或改 onedir 模式换取秒开（docs/06 有对比） |
| 3 | node/mvn/java 等外部依赖探测要防"探测卡死" | 全部探测带 2 秒超时，超时按"未安装"处理 |
| 4 | 杀进程树在 Windows 上偶有权限问题（服务提权进程） | v0 只做普通 taskkill，失败时提示用 Tool_ProcessPortManger 处理 |
